# Форма об'єкта нерухомості і медіатека

*Статус: реалізовано 2026-10-08. Основа — три дослідження (поля порталів,
UX довгих форм і мап, технології медіа); джерела нижче.*

## 1. UX-рішення

- **Одна сторінка з секціями, не майстер.** Агент заповнює форму багато
  разів на день — для частих професійних задач NN/g не радить wizard
  ([NN/g Wizards](https://www.nngroup.com/articles/wizards/)); GOV.UK
  дозволяє групувати питання для внутрішніх інструментів
  ([GOV.UK question pages](https://design-system.service.gov.uk/patterns/question-pages/)).
  Ліворуч — липка навігація секцій зі статусом (✓ / не заповнено / помилка),
  відсоток заповненості й клікабельний список "що ще потрібно".
- **Тип — першим** (чіпи), він визначає решту: поля, що не стосуються
  типу, приховуються, але значення лишаються в стані (перемикання типу
  назад нічого не губить) і не надсилаються.
- **Автозбереження чернетки** через 1,2 с після зміни + Ctrl/Cmd+S +
  попередження при виході з незбереженими змінами. Індикатор "Збережено о …".
- **Валідація "reward early, punish late":** коректність значень
  (поверх ≤ поверховість, житлова ≤ загальна, формат кадастрового номера)
  — одразу від сервера; "обов'язкове поле" — лише після спроби "Завершити".
  Помилка — біля поля, не лише зверху.
- **Кількості — чіпи** `1 2 3 4 5+` (один дотик на телефоні, "5+"
  відкриває поле); числа — `inputMode="decimal"`, кома як роздільник,
  одиниця всередині поля (м², сот., м).
- **Адреса:** пошук з автодоповненням → пін на мапі (клік/перетягування)
  → структуровані поля, які завжди можна виправити. Перетягування пін-а
  *пропонує* нову адресу, а не перезаписує введену мовчки.
- **Медіа:** drag-and-drop і кнопка вибору; на телефоні — окрема кнопка
  камери; прогрес кожного файлу; порядок перетягуванням (і стрілками —
  без миші); "Зробити обкладинкою" переносить фото першим; підписи;
  видалення зі "Скасувати" (5 с); переглядач з ←/→/Esc.
- **Мобільний:** секції одна під одною, липка нижня панель
  (статус збереження · % · "Завершити").

## 2. Поля й обов'язковість

Обов'язкові для завершення — мінімум, який DIM.RIA вимагає для публікації
кожного типу (XML-специфікація, https://dom.ria.com/uk/xmldoc/). Джерело
правди — `PropertyRules` (бекенд), фронт отримує їх з
`GET /api/properties/form-schema`.

| Тип | Обов'язкові (+ ціна для всіх) |
|---|---|
| Квартира | місто, вулиця, будинок, ринок, загальна площа, кімнати, поверх, поверховість |
| Будинок | місто, вулиця, загальна площа, площа ділянки, кімнати, поверховість, матеріал стін |
| Ділянка | місто, площа ділянки, цільове призначення |
| Комерційна | місто, вулиця, будинок, тип приміщення, площа, поверх, поверховість |
| Інше | місто, площа |

Рекомендовано (не блокує): точка на мапі, опис від 100 символів, ≥ 5 фото.

Переліки (матеріал стін, стан, опалення, призначення ділянки) — скорочені
до найуживаніших значень DIM.RIA; Java enum `Property.*`. Ділянка —
у сотках в інтерфейсі, у БД — м². Українська специфіка, що вже в моделі:
кадастровий номер, "резервне живлення" / "укриття" (відключення світла).
Ціна — на лістингу (чернетка продажу), з історією змін.

## 3. Мапа й геокодування

- **MapLibre GL + OpenFreeMap** (векторні тайли без ключа й лімітів,
  атрибуція обов'язкова; https://openfreemap.org/). URL стилю — у
  `VITE_MAP_STYLE_URL`. Мапа вантажиться ліниво (лише в редакторі).
- **Геокодування — лише через бекенд** (`/api/geo/search|reverse`,
  інтерфейс `GeocodingProvider`): один пункт заміни провайдера, кеш,
  ключі не потрапляють у браузер. Зараз — **Photon** (komoot), створений
  для автодоповнення. Публічний інстанс — тільки для розробки (без
  гарантій, тротлінг). Nominatim для автодоповнення заборонений
  політикою OSMF.
- **До проду:** власний Photon з екстрактом України/ЄС (той самий API)
  або комерційний провайдер (Visicom має найкраще покриття номерів
  будинків в Україні — потребує договору).

## 4. Медіа

- **Завантаження через бекенд** (multipart), не напряму в S3: тип файлу
  перевіряється за сигнатурою (magic bytes), фото перекодовуються до
  запису. Перехід на прямі presigned POST — коли обсяги відео цього
  вимагатимуть (і після перевірки підтримки POST policy у RustFS).
- **Фото й планування:** EXIF-орієнтація застосовується, далі перекодування
  в JPEG 1920 px (large) і 480 px (thumb). **EXIF/GPS не потрапляють у
  сховище; оригінал не зберігається.** PNG з прозорістю — на білому тлі.
  Захист від "декомпресійних бомб" (> 50 Мп). HEIC відхиляється з
  інструкцією (вільного Java-декодера немає; iOS Safari з `accept="image/*"`
  зазвичай сам конвертує в JPEG).
- **Відео:** MP4/MOV до 200 МБ зберігаються як є й програються з
  підписаного посилання; або посилання YouTube/Vimeo (лише https і
  дозволені хости). HEVC з iPhone може не грати в Chrome — транскодування
  ffmpeg відкладено.
- **Віддача:** бакет приватний, браузер отримує тимчасові (1 год)
  підписані посилання. Ключі: `tenants/<tenant>/properties/<id>/media/<media>/…`.
- **Ліміти:** 50 фото, 20 планувань, 5 відео/посилань на об'єкт; фото
  до 20 МБ, відео до 200 МБ.
- **Паралельні завантаження:** обробка й запис у сховище — паралельно;
  короткий крок реєстрації в БД серіалізується advisory-блокуванням
  Postgres на об'єкт (інакше два файли одночасно ставали "першим фото").

## 5. Відкриті питання / наступні кроки

- Самостійний Photon (або Visicom) і власні тайли/MapTiler перед продом.
- Транскодування відео (ffmpeg, окремий контейнер), постер-кадр.
- WebP/AVIF-варіанти (libvips) і CDN для опублікованих фото.
- "Дублювати об'єкт" (новобудови — багато схожих юнітів).
- Синхронізація з порталами (DIM.RIA XML, OLX API) — переліки вже
  сумісні з DIM.RIA.
- Чистка "сиріт" у сховищі (видалені об'єкти/агенції) — фоновий job.
