# Воркфлоу продажу об'єкта: від заведення до закриття

*Статус: пропозиція для обговорення, 2026-10-09. Уточнює domain-model.md §6
на основі того, що вже реалізовано (форма об'єкта, медіатека, клієнти,
демо-дані «Одеса Рієлт»).*

## 1. Об'єкт і лістинг — навіщо дві сутності

**Об'єкт (Property)** — фізична річ: адреса, параметри, фото, документи.
Існує стільки, скільки існує сама квартира. **Лістинг (Listing)** — комерційна
пропозиція щодо об'єкта: продаж чи оренда, ціна, мандат від власника,
статус, дати. У об'єкта за життя буває кілька лістингів: продали у 2024,
новий власник виставив у 2026; або продаж і оренда паралельно.

| | Україна | ЄС / світ |
|---|---|---|
| Термін у агентів | «об'єкт», «оголошення» | listing (MLS, Rightmove), *anuncio* (idealista), *Inserat* (ImmoScout) |
| Де живе ціна | у «оголошенні» на порталі | у listing |
| Мандат з власником | договір з власником, часто неформальний | обов'язковий (Maklervertrag, mandat de vente) |

Висновок: **у даних лістинг потрібен, в інтерфейсі українському агенту
слово «лістинг» показувати не варто.** Лістинг стає вкладкою **«Продаж»**
на картці об'єкта (ціна, власник, мандат, статус, історія цін), а окрема
сторінка «Лістинги» прибирається. Для ЄС та сама вкладка, лише інша
термінологія в перекладі.

## 2. Повний шлях об'єкта

```
Чернетка ──► Заведено ──► У продажу ──► Є покази ──► Є офер ──► Під завдатком ──► Продано
   │            │             │            │           │             │
   форма     +власник      публікація   календар     торг      чекліст угоди     архів
   фото      +мандат       +ділитись    фідбек     контр-офер  документи/нотаріус
             +ціна                                               розрахунок/реєстрація
                              └──────────────── Знято з продажу / Мандат закінчився
```

Етапи й що на них робить агент:

1. **Заведення** (готово): форма, фото, адреса. Результат — об'єкт `ACTIVE`.
2. **Підготовка до продажу** (далі): власник як контакт, мандат
   (ексклюзив/ні, строк, комісія), стартова ціна → лістинг `ACTIVE`.
   Публічна сторінка об'єкта + кнопка «Поділитись» (посилання для Viber /
   Telegram / email). Пізніше — вивантаження на DIM.RIA / OLX.
3. **Вхідний інтерес**: заявка з публічної сторінки, дзвінок, рекомендація →
   контакт (вже є) + «інтерес» клієнта до конкретного об'єкта.
4. **Покази** — ядро щоденної роботи, окремий модуль (§3).
5. **Офер**: сума, умови текстом, «дійсний до»; контр-офер від продавця;
   прийняття → угода, лістинг `UNDER_OFFER`.
6. **Угода**: чекліст із шаблону агенції (для UA: завдаток/попередній
   договір → перевірка документів і витяг → оцінка → нотаріус → договір →
   розрахунок → реєстрація права → ключі/акт); дедлайни, відповідальні,
   документи до кроків. Закриття → лістинг `SOLD`, об'єкт архівується
   або лишається для історії.
7. **Наскрізне**: таймлайн об'єкта і клієнта (усе, що сталося, одним
   списком), задачі з дедлайнами, нагадування.

## 3. Модуль показів (Showings)

**Сутність `Showing`:** об'єкт, клієнт(и), агент, час початку, тривалість
(дефолт 45 хв), статус `SCHEDULED / CONFIRMED / COMPLETED / CANCELLED /
NO_SHOW`, нотатки перед показом, фідбек після (§3.3), хто скасував і чому.

### 3.1 Планування

- Створити показ можна з трьох місць: картка об'єкта («Запланувати показ» →
  обрати клієнта), картка клієнта (обрати об'єкт), календар (обрати обоє).
- Перевірка накладок: той самий агент у той самий час → попередження;
  той самий об'єкт у той самий час → заборона (власник не може приймати двох).
- Один слот — кілька клієнтів (груповий показ) допускається.
- Телефон власника/ключі: на вкладці «Продаж» об'єкта є поле «Доступ»:
  ключі в офісі / домовлятися з власником / код замка. Агент бачить це при
  плануванні.

### 3.2 Календар

- **Мій день / тиждень** для агента: покази, задачі, дедлайни угод.
- **Агенція** для керівника: усі агенти стовпчиками (тиждень).
- Експорт у iCal (підписка на календар) — щоб покази з'являлися у Google
  Calendar / iPhone агента без інтеграції OAuth. Двостороння синхронізація —
  пізніше.

### 3.3 Зв'язок з клієнтом

Українські агенти працюють через телефон, Viber і Telegram; email —
рідко. Тому у Фазі 1 не будуємо відправку повідомлень, а робимо так, щоб
із системи було зручно **поділитися** і **зафіксувати**:

- «Поділитись об'єктом» → публічна сторінка з фото й параметрами (без
  точної адреси, якщо так налаштовано), готовий текст для месенджера.
- «Надіслати підтвердження показу» → готовий текст «Четвер, 15:00,
  Дерибасівська 10, зустрічаємось біля під'їзду, Ігор +380…» для копіювання
  у Viber/Telegram, плюс `.ics`-файл для клієнта.
- Журнал контактів на картці клієнта: дзвінок / повідомлення / зустріч з
  нотаткою і датою (ручний запис, 2 кліки).
- Фаза 2: SMS/Viber через провайдера, нагадування клієнту за день до показу.

### 3.4 Фідбек після показу

Одразу після показу агент (з телефона) заповнює 20-секундну форму:
- зацікавленість 1–5;
- причина «ні»: ціна / стан / локація / планування / інше (чіпи);
- коментар;
- наступний крок: повторний показ / чекаємо рішення / офер / не підходить.

Фідбек бачить і керівник, і (у вигляді звіту) власник об'єкта — «за два
тижні 6 показів, середня оцінка 3,2, головне заперечення — ціна». Це сильний
аргумент для зниження ціни і одна з речей, за які власники цінують агенцію.

Після показу система сама створює задачу «Передзвонити клієнту» на +2 дні,
якщо наступний крок не вибрано.

### 3.5 Підбір: кому показати

У клієнта з'являється **запит** (що шукає): тип, кімнати, бюджет, райони,
обов'язкові умови (укриття, паркінг). Тоді:
- на картці об'єкта — «Підходить 4 клієнтам» зі списком;
- на картці клієнта — «Підходить 7 об'єктів».
Це дешевий, але дуже корисний матчинг на SQL-фільтрах; без ML.

## 4. Як це виглядає в інтерфейсі

- **Картка об'єкта** стає головним екраном з вкладками:
  `Огляд · Продаж · Покази · Офери · Угода · Історія`. Форма редагування —
  всередині «Огляду».
- **Картка клієнта**: профіль, запит, інтереси (об'єкти), покази, офери,
  журнал контактів.
- **Календар** — окремий пункт меню.
- **Головна** замість двох цифр: «Сьогодні: 3 покази, 2 задачі, 1 нова
  заявка», далі найближчі події.
- Мобільний режим для показів: сьогоднішній список → один тап «Завершити
  → фідбек».

## 5. Порядок реалізації (кожен крок — робочий інкремент)

1. **Продаж об'єкта** — *реалізовано 2026-10-09*: вкладка «Продаж»
   (ціна, власник, мандат, комісія, доступ, приховування адреси), стейт-машина
   лістингу (`DRAFT → ACTIVE → UNDER_OFFER → SOLD`, `WITHDRAWN`, `EXPIRED` з
   щоденним job), кілька відповідальних агентів (LEAD + співагенти), таймлайн
   об'єкта (вкладка «Історія»), «Поділитись» (публічне посилання + готовий текст),
   публічна сторінка агенції `/p/<slug>` (фільтри в URL, сортування, список + мапа
   з ціновими пінами, картки з бейджами «Нове»/«Ціну знижено») і об'єкта
   (галерея, факти, зручності, мапа або коло ~400 м, агент, форма заявки →
   таймлайн), кабінет власника `/owner/<token>` (90-денне посилання без пароля,
   лише свої об'єкти і лише owner-visible події). Сторінку «Лістинги» прибрано.
   *Ще не зроблено з цього кроку:* кластеризація пінів на мапі, SSR/OpenGraph
   для прев'ю в месенджерах, UAH-еквівалент ціни, «Дублювати об'єкт».
2. **Клієнт глибше** — *реалізовано 2026-10-09*: картка клієнта
   (`/clients/<id>`): профіль, «Що шукає» (тип, кімнати, бюджет, площа,
   райони, ринок, обов'язкові зручності), «Підходять об'єкти» з поясненням,
   за якими умовами збіглося; на вкладці «Продаж» об'єкта — «Підходить
   клієнтам». Журнал контактів (дзвінок/повідомлення/зустріч/нотатка)
   пишеться в таймлайн клієнта. Підбір — жорстка відповідність усіх
   заповнених умов, без конвертації валют (інша валюта = не підходить).
3. **Покази**: сутність, планування з трьох точок, накладки, календар
   день/тиждень, фідбек, авто-задача, iCal-підписка, звіт власнику.
4. **Офери**: ланцюжок, прийняття → угода, резервні офери.
5. **Угода**: шаблони чеклістів агенції (дефолт UA), кроки, документи до
   кроків, закриття/скасування.
6. **Головна і задачі**: «мій день», нагадування в застосунку.

Оцінка — по 1–2 тижні на крок при поточному темпі; покази (крок 3) —
найбільший.

## 6. Рішення (2026-10-09)

1. Вкладка називається **«Продаж»**.
2. Покази у Фазі 1 записує **лише агент**.
3. **Публічна сторінка** — робиться одразу, з фільтрами, пошуком і мапою
   (зібрано з DIM.RIA/LUN/Rightmove/Idealista — див. research у коміті).
4. На об'єкті **кілька відповідальних агентів** (один головний).
5. **Звіт власнику** формується автоматично з таймлайну; власник бачить лише
   свої об'єкти (посилання без пароля).

## 6a. Початкові питання (для історії)

1. **Назва вкладки для лістингу** в UI: «Продаж» (пропозиція) чи
   «Пропозиція» / «Оголошення»?
2. **Запис на показ лише агентом** (пропозиція для Фази 1) чи вже зараз
   самозапис клієнта за посиланням на вільні слоти?
3. **Публічна сторінка об'єкта** — робимо в кроці 1 (потрібна для
   «Поділитись») чи відкладаємо?
4. **Два агенти на об'єкті**: лише відповідальний (лістер) чи ще
   «показує інший агент» (співагент) з поділом комісії? Впливає на модель
   показів і на угоду.
5. **Звіт власнику** — автоматичний (посилання для власника) чи агент
   формує вручну PDF/повідомлення?
